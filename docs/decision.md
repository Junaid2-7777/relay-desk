# Project decision

Select **Deadline Relay** for Homingo’s Agents A3 statement. The first proposal, Commit Rehearsal, asked a judge to take a venue after approval. It proposed version checks and recovery. Its central decision could be handled by filtering available rooms. Deadline Relay gives the agent a continuing task with different people responsible for each stage, four observed versions of the public schedule, and a case whose outcome the judge can change. [Original proposal](https://github.com/JunaidAhamed-7777/commit-rehearsal) · [Official Agents statements](https://hackathon.homingo.co.in/hackathons/edition-01/problem-statements#agents)

We screened candidates using the event rubric and four practical requirements. A viewer should quickly understand whose problem it is. A judge should be able to alter a material input live. Success should leave independent records that can be scored. A solo build should be able to show the hard part without privileged integrations or real personal data. No customer interviews were conducted in this research pass. Product adoption remains a hypothesis.

## Finalists

### Deadline Relay · A3

- **Moment.** A student is waiting for somebody else to meet their deadline. Introduce a real official extension, return the application in the synthetic school console, then issue an acknowledgement. The agent changes the two affected calendar events in place and keeps the case open until both the simulated school and district verify it.
- **Why an agent.** The agent must reconcile natural-language notices and a changing case history before choosing to wait, ask the student for a correction, or prepare a specific follow-up. Schema validation and native state transitions establish permission and outcome. Comparing against a typed workflow isolates where the model actually helps.
- **What would sink it.** A reminder assistant could reproduce the first scene. The demo needs a correction that changes who owns the work, and separate provider records for acknowledgement and verification. Buddy4Study already offers alerts, reminders and status tracking. The proposed contribution is to recover a particular already-filed case and verify the handoff. [Buddy4Study application guide](https://www.buddy4study.com/article/mastering-scholarship-applications-on-buddy4study) · [NSP public scheme listing](https://scholarships.gov.in/All-Scholarships)

### 72 Hours · A2

- **Moment.** A farmer-producer organisation receives conflicting loss reports near an intake deadline. One report is duplicated, another is missing evidence, and an insurer accepts a third but drops the reply. The agent closes only cases that have independently acknowledged submissions, then reconciles any later insurer decisions and payments in the simulator.
- **Strength.** It has high human stakes and real work across the insurer, assessment and reconciliation steps. An agent could add value by identifying what evidence is missing from multilingual reports. Existing government systems already handle submission and assessment. [PMFBY Farmer Corner](https://www.pmfby.gov.in/policyclaim/farmer) · [Crop Loss Assessment Platform](https://pmfby.gov.in/clapweb/faq)
- **Why it lost.** Crop, policy, district and loss category affect the real rules. The government’s paddy announcements did not establish a simple nationwide rule for the candidate. Local insurer and survey integration would each need synthetic stand-ins. With two weeks and one developer, the hardest parts of the demo would be difficult to distinguish from fixture assumptions. [Policy announcement](https://www.pib.gov.in/PressReleasePage.aspx?PRID=2191224&lang=1&reg=3) · [Lok Sabha response, 4 August 2026](https://www.pib.gov.in/PressReleasePage.aspx?PRID=2294455&lang=1&reg=1)

### Every Transfer · A3

- **Moment.** An accessible rail itinerary breaks at one transfer. The agent discovers an alternative and holds a compatible train, assistance and last-mile ride before relinquishing the affected reservation. The judge sees which transfer failed and which providers accepted the replacement.
- **Strength.** A time-dependent map and three service receipts would be an excellent demonstration. India’s CAG rail audit records real infrastructure and access gaps. Accessible trip services already offer verified planning and booking. [CAG railway accessibility audit](https://saiindia.gov.in/en/audit-report/details/125975) · [IRCTC wheelchair service](https://www.irctctourism.com/wheelchair) · [Planet Abled](https://planetabled.com/travel-with-us)
- **Why it lost.** Public data can demonstrate an elevator outage elsewhere, but the research did not verify machine-readable Indian station-level availability or public APIs that support the proposed holds and cancellations. The operational promise would depend on fabricated capabilities in more places than the scholarship demo. [MTA public outage feeds](https://api.mta.info/) · [TfL station access guide](https://content.tfl.gov.uk/step-free-access-and-toilet-data-guide.pdf)

### Counterexample Compiler · A1

- **Moment.** A QA agent takes a passing stateful workflow and finds the smallest sequence of ordinary business events that makes it produce a false success. It exports the exact regression and reruns it against the repair.
- **Strength and cutoff.** In a model-free probe of eight event combinations, two events were jointly necessary to create a duplicate effect. The provider committed before losing its reply, then the date rolled over so a badly designed retry picked a new idempotency key. A stable operation key removed the failure in the probe. This establishes that a small reproducible witness is possible. The research did not establish an advantage for a model over an equivalent typed enumerator. Existing simulation tools already provide twins, behavior checks and chaos testing, so discovery yield or reduced test authoring would have to be measured head to head. [AgentTwin](https://github.com/dataagentsai/agenttwin) · [Rightbrain chaos testing](https://docs.rightbrain.ai/docs/production/chaos-testing)

### Evidence Lock · A1

- **Moment.** A retraction arrives and marks one generated claim, a computed table, and a downstream draft as needing review. The research agent traces what depended on the paper, recomputes the affected values, and produces a scoped edit or an explicit abstention.
- **Strength and cutoff.** A live Crossref probe returned 12 records with 18 update entries. Some entries had repeated publisher and Retraction Watch representations, while others used the same DOI for source and target. Ingestion is feasible and meaningful mapping requires care. Existing retraction alerts, verification tools and research already cover parts of the concept, including claim-level correction propagation. A reliable demo would need independent evidence that the agent changed exactly the dependent artifacts and preserved unaffected content. [Crossref update data](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/) · [Zotero retraction notices](https://www.zotero.org/blog/retracted-item-notifications/) · [Correction Reach](https://www.mdpi.com/2304-6775/14/4/78)

## Additional routes screened

- **A1 three-way swap exchange.** Three owners can jointly swap bookings even when no pair can trade. The matching proof is easy to show. The hard problem is persuading a judge that a model contributes beyond a solver and a familiar approval screen.
- **A1 cross-model resume.** A second model resumes a partially complete job using typed obligations and provider receipts. A convincing demo needs a fair comparison to ordinary durable state machines and independently implemented providers.
- **A1 private delegation receipts.** A second agent performs a narrower authorized task with a short-lived mandate. The capability is useful but requires a stronger initial workflow and proof at each provider boundary.
- **A2 targeted recall drills.** One lot moves during a simulated recall and the agent has to account for it. The openFDA sample proved broad recall and lot text is accessible. It did not expose authoritative partner stock, and a direct incumbent already does batch-level holds, acknowledgements, and mock recalls. [openFDA example queries](https://open.fda.gov/apis/food/enforcement/example-api-queries/) · [Trustwell FoodLogiQ Recall](https://www.trustwell.com/products/foodlogiq/recall/)
- **A2 disputed invoice desk.** Trace a late payment through purchase order, proof of delivery, buyer response and payment reconciliation. It has a credible buyer and strong public evidence of a wider delayed-payment problem. Large suites already resolve disputes. A narrow segment would need first-hand validation before claiming a wedge. [MSME Samadhaan](https://ramp.msme.gov.in/ramp/RAMP-initiative/msme-samadhaan/msme-samadhaan) · [HighRadius disputes](https://www.highradius.com/software/order-to-cash/collections-management/dispute-resolution/)
- **A2 tender amendment desk.** One corrigendum invalidates an already prepared bid and the agent rebuilds only affected paperwork. An existing product explicitly offers corrigendum reanalysis and preparation workflows. [BidShakti features](https://bidshakti.com/features)
- **A3 bereavement administration.** The agent tracks multiple organizations through a family's account closure journey. The data access, sensitive documentation and frequency of disputed cases make the end-to-end prototype a poor fit for the event window.

## Evidence from the winning design probe

Fetched four Ministry notices directly and verified their separately published application, institute and district dates. From the first to final notice, each milestone moved 76 days. A fixed “application date plus 30 days” rule is already wrong for the September notice, which gives 31 October for district verification. The public listing independently corroborates the late October NMMSS dates. The local HTTP request to the listing was intermittent, so the runnable project needs a dated fallback snapshot and a visible source freshness indicator. [Four notice versions and the portal listing](sources.md#nmmss-timeline)

A small model-free replay fed the three revisions after the initial notice into a typed fixture. On each revision, exactly two existing reminder keys changed. Replaying the same revision, replaying an older one, and adding a mismatched scheme or year caused zero reminder changes. A direct same-version date conflict stopped for review. The script used in-memory records with dates typed from the official notices. This tests the scope and date-change premise. Model extraction, live provider reliability and workflow success remain to be measured in the build.

The first build gate is stricter than this probe. Bring up an independent calendar and case service, replay the October notices, and prove that an acknowledgement cannot close the case. After that passes, measure whether the live agent handles differently formatted notices and variations on the correction scenario more reliably than the simplest comparable workflow.
