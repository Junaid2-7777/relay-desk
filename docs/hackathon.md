# Homingo Hack Days · Edition 01

Deadline Relay is a solo Agents entry for **A3 · A personal staff for everyone**. The A3 brief asks for a trusted agent that takes real administrative work off someone’s plate. Deadline Relay takes responsibility for one task after a scholarship filing. It follows changing public deadlines, reconstructs the next action when a case comes back, updates an isolated local calendar, and keeps the case open until the right actor’s evidence arrives. [A3 official problem statement](https://hackathon.homingo.co.in/hackathons/edition-01/problem-statements#a3) · [Agents track](https://hackathon.homingo.co.in/tracks#agents)

## What the judges should see

- **Problem fit and impact** — Show one already-filed case stuck between student, institute and district steps. Ground the need in the government’s public schedules and audit. [Source evidence](sources.md)
- **Technical depth** — Show the agent fetching public records, matching deadlines by scheme and stage, responding to a returned case, and planning across independently readable state. Let judges inspect actual writes to the isolated calendar and the simulated outbox.
- **Reliability and evaluation** — Replay real source revisions, inject synthetic case events, and measure whether the agent preserves completed steps, handles ambiguity, avoids duplicate actions and waits for valid verification evidence.
- **Product and experience** — Put the next action, its owner and deadline on one screen. Show the source behind the deadline and distinguish local preparation from the authority’s recorded action.
- **Demo and communication** — Run the recovery live using synthetic student, institute and district actors. Show a calendar update and a controlled local draft. Finish on the simulated authority receipt. [Edition judging rubric](https://hackathon.homingo.co.in/hackathons/edition-01#judging)

The Agents track also emphasizes realistic task completion, sound tool use and planning, and safety through limits, confirmation and fallback behavior. The official statement page asks for working evidence, measured results, ambition on the difficult part and a plausible route to broader use. ## Rules and submission

Use original work built during the edition. Pre-kickoff planning is allowed. Open-source libraries, public APIs, pre-trained models and AI coding tools are permitted. List what was actually used in the README and be able to explain the implementation. Use open or synthetic data and exclude real people’s personal data. The project uses public deadline fields and synthetic case records, with isolated calendar writes and a local outbox. Keep credentials and private registration details out of the repo and recording.
